# Limitations

- The graph is static and bounded by `impact.max_dependency_depth` (two by default). Dynamic imports, reflection, runtime module registration, and generated files are reported as uncertainty rather than claimed complete. TypeScript `paths`, Python `src/` layouts, nested Go modules, Rust workspace crates, and C/C++ `compile_commands.json` include paths are resolved when their metadata is available.
- Coverage is evidence of executed lines, not proof that an assertion was meaningful. Changed-line coverage is reported separately from global coverage.
- “Covered by modified tests” is a conservative import/provenance heuristic when the coverage format does not record which test caused a hit; it is not presented as a runtime proof of assertion ownership.
- Mutation testing is opt-in, scoped, bounded, and adapter-based. A surviving mutant is evidence for review, not proof that production code is incorrect.
- Base/head test comparison needs a clean Git revision and a configured command. If the base cannot install or run, the result is `unknown`, not a failure.
- CI execution history is not available to a local tool. Coverage artifacts and optional report metadata are used as evidence; missing metadata remains visible.
- The parser supports TypeScript/JavaScript through the TypeScript compiler API and Python, Go, Rust, C, and C++ through bounded deterministic adapters. Optional `validation.toolchain_checks` adds read-only syntax/front-end checks for the non-JavaScript languages; a missing toolchain is reported as unavailable, and parser uncertainty remains distinct from a failed syntax check. It does not promise complete runtime behavior for any language.
- Python `importlib`/`__import__`/evaluation, Go build and generate directives, Rust macro/derive/conditional compilation, and C/C++ preprocessing are explicit unknowns rather than silently treated as complete.
- The hosted Worker authorizes billing, assurance metadata, and invitation creation against D1 membership, role, feature, billing-status, and seat-limit rows rather than trusting the WorkOS organization id alone. Verified WorkOS webhook/events now provision organization, user, membership, and invitation state with fail-closed role/status mapping; an authenticated sync route repairs the current user’s selected organization; and an opt-in cursor-based WorkOS Events API consumer advances missed changes. Staging D1 deployment, invitation API/UI wiring, and the selected seven-day replay window are in place. R2 enablement, rotated live provider credentials, WorkOS webhook registration, full historical bootstrap, organization switching, repository-level entitlement checks, and live provider validation remain operational prerequisites.
